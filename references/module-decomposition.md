# 代码仓库模块拆解手册

> 供 `note-ai` 在「代码仓库笔记」（多模块）场景下使用：先拆模块，再逐篇写笔记。
> 本手册只解决 **"切几篇、每篇覆盖什么"**；每篇怎么写由 `templates/code-outline.md` 负责，索引怎么写由 `templates/code-repo-index.md` 负责。

---

## 0. 何时启用

同时满足以下两条才启用：

1. 目标是**代码仓库**（不是单篇论文、不是单个独立文件）；
2. 用户没有显式给出要写的 class 列表（给了就按 `SKILL.md` 5.8 的多 class 豁免直接写，不拆）。

不启用的情况：

- 论文/技术文档笔记 → 走 `templates/paper-outline.md`；
- 单文件、单类的小模块（如只有一个 `Attention` 实现）→ 一篇即可；
- 已有 `decompose` 产物（`.note/_arch/`）或目录内已有 `readme.md` → **直接复用**其模块划分与编号，只做增量追加（见 §4 第 4 条），不要重新拆一遍。

---

## 1. 第一原则：三种切分依据

模块必须同时满足**至少两条**下列依据，否则不成立：

| 依据 | 判断问句 | 通过的样子 |
|------|----------|------------|
| **运行时职责** | 这个模块在运行时"做哪一件事"？能用一个动词短语说完吗？ | "把点云压成 latent" / "在 latent 上做去噪" / "把数据读成一个 batch" |
| **依赖方向** | 谁调用谁？能不能做到"改 A 不用改 B"？ | A 只被 B 引用，B 改内部实现时 A 不用动 |
| **共同变更原因** | 会因为这个模块**同一类需求**一起改吗？ | "换 latent 维度"只动编码器与扩散模型两个模块，不会牵扯数据集 |

**反例（都不满足三条依据）**：

- ❌ 按目录切：`models/` 一篇、`utils/` 一篇——`utils/` 里往往同时住着"位置编码"和"分布式工具"，职责完全不同。
- ❌ 按文件切：一个 `.py` 一篇——文件的组织常常是历史遗留，与运行时职责无关。
- ❌ 按类的数量平均切：三个类就切三篇——会把"薄壳包装类"（`PreNorm`）和"整个 VAE"（`KLAutoEncoder`）放在同一权重。

## 2. 粒度规则（硬规则）

| 编号 | 规则 | 理由 |
|------|------|------|
| **R1** | 一个模块 = 一种运行时职责；职责若能用"and"连成两句，就该拆 | 保证"一句话职责"可写 |
| **R2** | 被其他模块当作**成员变量/构造参数**调用的类，**不单独成篇**；只在调用方笔记里简短介绍。**"不展开" ≠ "另开一篇"**：除非同时满足 R5，否则这个类**不产生任何新文件** | 与 `SKILL.md` 5.8「子模块不展开」一致；否则 `PreNorm`、`Block`、`nn.Linear` 都会各占一篇 |
| **R3** | 只有 1–2 个函数、且没有独立数据契约的**入口脚本**（`main*.py`、`engine*.py`、`sample*.py`）→ **合并成一篇"流程篇"** | 单篇信息密度太低，且它们本来就是同一条流水线的不同阶段 |
| **R4** | 一篇笔记覆盖的代码量落在 **100–500 行、1–3 个核心符号**；超过则继续拆，不足则并入上游 | 低于 100 行撑不起模板 1–7 章；高于 500 行读者读不完 |
| **R5** | 低层共用原语（`Attention`、`RMSNorm`、位置编码、`FeedForward`）**独立成篇的判据**：被 ≥2 个上层模块复用 **或** 是论文/设计的关键创新点 | 只被一个模块用、又不是创新点 → 并入调用方 |

**R3 的判定细则**（"流程篇"最容易切错）：

- 这些脚本共享同一套数据契约（同一个 batch 字典、同一个 loss 接口）→ 合并；
- 其中某个脚本本身包含一个**有独立生命周期的类**（如 `EDM` 采样器持有 `sigma_min/max` 状态）→ 该类单独成篇，脚本留给流程篇；
- 流程篇的"参考代码"行写**函数名**而不是类名（如 `engine_*.train_one_epoch`、`main`），并在 §1 模块定位里说明"它们是函数不是类"。

## 3. 拆解算法（按序执行，6 步）

1. **列符号清单**：`grep` 出每个文件的顶层 `class` / `def`（不含类内方法），记下"文件 → 符号"。
2. **标调用边**：对每个符号，找它出现的位置（`__init__` 里被实例化、`forward` 里被调用、被 `main` 调用），得到"谁用谁"。
3. **找入口**：`main` / `train` / `infer` / `pipeline` / `sample` —— 从入口出发做拓扑排序，这是**阅读顺序**的骨架。
4. **沿数据流切段**：把入口的数据流切成"输入 → 编码 → 压缩/瓶颈 → 主干 → 解码 → 输出 → 评估"若干段，**每段是一个候选模块**。段与段之间的接口（张量形状、字典键）就是模块边界。
5. **套 R1–R5 合并/拆分**，得到 3–9 个模块；再跑一遍**反向检验**：
   - 把"职责"一列单独抽出来给没读过代码的人看，能否解释"为什么需要这个模块"？
   - 任意两个模块的"覆盖符号"是否有交集？有 → 合并或重切。
   - 是否存在"只被自己用、且不足 100 行"的模块？→ 并入上游（R4）。
   - 是否存在"一个模块里两个职责毫不相干"？→ 拆开（R1）。
6. **写模块表**（编号 / 模块 / 覆盖符号 / 所属阶段 / 一句话职责），确认后再进入大纲阶段。

> 3–9 个模块是经验区间：少于 3 说明切得太粗（多半在按文件切）；多于 9 说明切得太碎（多半把子模块展开成了篇）。

## 4. 命名、编号与目录

1. **子目录**：优先复用目录里**已有**的笔记目录名（`src-note/`、`code_note_xxx/`）；没有则用 `<仓库名>-note/` 或 `src-note/`。
2. **文件名**：`NN-<主符号>.md`
   - `NN`：**新目录从 `01` 起用两位数字；既有目录跟随既有位数**（如 `TripoSG/.note/src-note/1-DiTBlock.md` 用单位数，就继续用 `8-…`）。**首次拆解**按依赖顺序排（底层 → 上层），此后只追加、不重排（见第 4 条）。
   - `<主符号>`：主类/主函数的**原始标识符，大小写保真**（`PointEmbed`、`KLAutoEncoder`、`LatentArrayTransformer`）；流程篇用简短英文名（`TrainingPipeline`）。
   - 禁止：中文文件名、空格、`snake_case` 与 `PascalCase` 混用（同一目录内必须统一）。
3. **命名冲突裁决**（目录里已有笔记时）：
   - 目录内**已有笔记** → 完全跟随既有约定（含大小写与位数）；
   - 全新目录 → 默认 `PascalCase` + 两位编号（与代码标识符一致，便于 `grep` 与 IDE 跳转）。
4. **编号只追加、永不重排**：新增模块一律取"当前最大号 + 1"。**稳定性优先于顺序**——若后来补一个底层模块，接受它拿到大号，也不许重排；合并/删除模块时**保留原编号**，在索引里标注"（已并入 `NN-xxx.md`）"，否则所有既有相对链接都会断。
5. **索引文件名固定 `readme.md`**（小写），与模块笔记同目录；其模板见 `templates/code-repo-index.md`。

## 5. 索引文件：拆解决策的唯一落点

`readme.md` 不是"可选项"，它承担六件事，缺一不可：

| 块 | 回答的问题 |
|----|-----------|
| 模块总表 | 一共有几个模块？每个覆盖哪些符号？ |
| 切分说明 | **为什么**这样切（只写理由，不写"是什么"） |
| 依赖关系图 | 谁依赖谁（只画依赖，不画调用时序） |
| 建议阅读顺序 | 第一遍怎么读（运行顺序）？改代码时怎么读（依赖顺序）？ |
| 笔记索引表 | 编号 ↔ 文件名 ↔ 模块 的映射 |
| 维护规则 | 新增/合并模块时编号怎么处理、索引何时回填 |

> 与 `templates/code-repo-index.md` 的六块一一对应；本表是"必须有什么"，模板是"长什么样"。

**同步义务**：每新增/删除/合并一个模块，都必须更新 `readme.md`；交付前用目录列表核对"索引里的文件都在磁盘上、磁盘上的笔记都在索引里"。

## 6. 常见错误

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 按文件/目录切 | 同一职责被拆散到两篇，或两个不相干职责挤在一篇 | 用 §1 三依据重切 |
| 把子模块展开成篇 | 笔记数量爆炸（`PreNorm`、`FeedForward` 各一篇），读者抓不住主线 | R2：只在调用方里简短介绍 |
| 把 5.8「子模块不展开」读成"给它另开一篇" | 孙模块也各占一篇，篇数翻倍、主线断裂；且新笔记里又要"不展开"它自己的子模块，递归下去没底 | R2：不展开 = 在调用方提一句，**不新建文件**；只有满足 R5 才独立 |
| 5 个薄脚本各写一篇 | 每篇不足 100 行，模板 1–7 章有大半写"本节不适用" | R3：合并成流程篇 |
| 按阅读顺序编号 | 增补一个底层模块时编号无处安放，只能重排 | 首次按依赖顺序，**此后只追加**、不重排 |
| 不写索引 | 跨篇的依赖关系只存在于作者脑子里，读者要自己拼 | 必写 `readme.md` |
| 索引与文件不同步 | 索引里的链接 404，读者以为笔记丢了 | 交付前逐条核对 |
| 拆完又改（进入填充后再重切） | 已写好的笔记与索引、交叉引用全部要返工 | 拆解在**大纲之前**一次性定稿；填充阶段只允许微调措辞 |

## 7. 完整示例：`3DShape2VecSet/src`

代码事实：一个两阶段仓库（VAE + latent diffusion），`models_ae.py`、`models_class_cond.py`、`util/`、4 个入口脚本。

拆解结果（7 篇）：

> 目标目录沿用 `TripoSG/.note/src-note/` 的既有约定（**单位数编号 + PascalCase**），故文件名为 `1-PointEmbed.md` … `7-TrainingPipeline.md`。若是全新目录，应改为 `01-PointEmbed.md` … `07-TrainingPipeline.md`。

| 编号 | 模块 | 覆盖符号 | 依据 |
|------|------|----------|------|
| 1 | 坐标编码 | `PointEmbed` | R5：被编码器 Q、编码器 K/V、解码器三处复用 |
| 2 | 注意力原语 | `Attention`（+`PreNorm`/`GEGLU`/`FeedForward`/`cache_fn`） | R5：两个上层模块复用，且是论文"可学习插值核"的落点 |
| 3 | KL 自编码器 | `KLAutoEncoder` + `DiagonalGaussianDistribution`（`AutoEncoder` 作为对照） | R1：独立职责"点云 → latent → occupancy" |
| 4 | 去噪骨干 | `LatentArrayTransformer`（+`BasicTransformerBlock` 等） | R1：只做 `x → F_x`，不理解 σ |
| 5 | EDM 外壳 | `EDMPrecond` / `EDMLoss` / `edm_sampler` | R1：预条件 + 采样 + 损失三种"σ 相关"职责聚在一起 |
| 6 | 数据管线 | `ShapeNet` / `AxisScaling` / 工厂函数 | R1 + 共同变更原因：字段顺序与两个引擎强耦合 |
| 7 | 训练与推进入口 | 4 个脚本 + `misc` / `lr_sched` | R3：4 个薄脚本合并成流程篇 |

**如果没有这套规则会怎样**（本次改动的动机来源）：按文件切会得到 4 篇（`models_ae` / `models_class_cond` / `util` / `入口脚本`），其中 `models_ae` 一篇要同时讲清位置编码、注意力、VAE 三件事，`util` 一篇要把"数据集字段顺序"和"分布式初始化"混在一起——粒度与主题都不对。

## 8. 交付前自检

- [ ] 模块数在 3–9 之间
- [ ] 每个模块能用一句话说清职责，且不含"and"
- [ ] 覆盖符号无交集；对照文件清单无遗漏
- [ ] 被调用的子模块没有单独成篇（R2）
- [ ] 薄入口脚本已合并（R3）
- [ ] 编号连续、按依赖顺序、未重排既有编号
- [ ] `readme.md` 已生成，且索引与磁盘文件一一对应
- [ ] 模块表已在写第一篇笔记**之前**给用户看过
